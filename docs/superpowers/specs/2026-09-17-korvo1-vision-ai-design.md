# Korvo-1 人脸与物体识别设计规格

日期：2026-09-17  
状态：待用户最终审核  
目标分支：`codex/vision-ai`  
基线分支：`refactor/korvo1-lvgl9-yokai` (`af471b3`)

## 1. 目标

在 ESP32-S31-Korvo-1 的现有「目目連の眼」页面中加入三项离线能力：

1. 检测并框出人脸；
2. 在设备端录入人员并识别身份；
3. 检测 COCO 80 类通用物体。

现有 LVGL 9、语音控制、天气、合成器、Wi-Fi、Bluetooth 和转场行为必须保持不变。语音命令「画像」「カメラ」及 `Camera` 继续进入同一个 Vision 页面。

## 2. 已确认的产品决策

- 采用现有固件直接集成 `esp_video + ESP-DL`，不移植整套 ESP-WHO。
- 页面提供「顔認識」和「物体認識」两个模式；两个模型互斥加载，不同时常驻。
- 录入时通过触屏输入姓名，每人采集 5 个合格特征，最多保存 10 人。
- 人员数据断电保留；支持查看、删除和重新录入。
- 只保存姓名、模型生成的特征及必要索引，不保存原始人脸照片。
- 识别成功、陌生人、无目标及运行失败都必须直接显示在画面上，全部使用日语。
- 本阶段只设计 Korvo-1；不同时适配 Mosaico 或 P4X。

## 3. 技术基线与兼容性门槛

- 硬件：ESP32-S31-Korvo-1 V1.1，OV3660 DVP 摄像头，800×480 RGB LCD，16 MB Flash，16 MB Octal PSRAM。
- SDK：项目当前使用 ESP-IDF master / v6.2.0 开发环境；实现必须记录实际构建提交。
- BSP：`espressif/esp32_s31_korvo_1_noglib == 1.0.1`；相机通过 `bsp_camera_start()` 与 `ESP_VIDEO_DVP_DEVICE_NAME` 初始化。
- 当前锁定 `espressif/esp-dl 3.3.11`，由 ESP-SR 间接引入；新增模型组件必须与 ESP-SR 2.5.3 共用同一 ESP-DL 版本，禁止在 `managed_components` 内直接改源码。
- 官方总览已把 ESP32-S31 列为 Human Face Detect、Human Face Recognition 与 COCO Detect 的支持芯片；但各模型子目录的表格与 Kconfig 仍只明确列出 S3/P4。因此实现的第一项任务必须是独立兼容性验证，不能直接假定 S3 模型配置可用于 S31。

兼容性验证必须先证明：

1. OV3660 可持续采帧并在 LVGL 页面显示；
2. 三个官方模型组件能以 `esp32s31` 目标编译、链接并处理固定测试图；
3. 模型、语音与三块全屏帧缓冲共存时仍有安全的 PSRAM/内部 RAM 余量；
4. 固件和模型能放入现有 16 MB Flash 分区布局；
5. 语音回归检查仍通过。

若任一项失败，先记录实际模型版本、内存、分区与错误日志，再决定升级同系列官方组件或调整分区。不得以修改第三方模型实现、移除语音或降低显示缓冲作为默认绕过方案。

## 4. 架构

### 4.1 组件

`vision_service` 是新增的唯一业务服务，负责：

- 初始化、启动、停止 OV3660；
- 获取帧并转换为预览和模型所需像素格式；
- 维护「人脸 / 物体」模式；
- 互斥创建和释放模型；
- 在工作任务中运行推理；
- 维护人员数据库；
- 通过一个有界结果队列把最新状态交给 LVGL。

`ui_vision` 负责：

- 显示相机预览；
- 显示人脸或物体框、标签和置信度；
- 切换模式；
- 发起录入、删除和重新录入；
- 显示日语状态与错误；
- 不直接调用相机、文件系统或 ESP-DL。

现有 `ui.c` 只负责页面生命周期：进入 `UI_SCREEN_VISION` 后启用服务，离开时停机并释放当前模型。不得把推理放进 LVGL timer 或事件回调。

### 4.2 数据流

```text
OV3660 / esp_video
        │
        ▼
采帧缓冲 ──► LVGL 预览
        │
        ▼
缩放 / 像素格式转换
        │
        ├── 顔認識: HumanFaceDetect → 对齐/特征 → HumanFaceRecognizer
        │
        └── 物体認識: COCODetect (YOLO11n 320 首选候选)
        │
        ▼
有界最新结果队列 ──► LVGL 框、标签、状态
```

队列只保留最新可显示结果；UI 来不及消费时丢弃旧结果，不能积压帧。相机和推理工作任务不得持有 LVGL 对象，也不得从非 LVGL 线程调用 LVGL API。

## 5. 页面与交互

### 5.1 主页面

- 顶部沿用现有 `create_screen_header()` 和「＜ ホーム」。
- 左侧约 520×310 为实时预览，识别框叠加在预览坐标系中。
- 右侧显示模式、主要结果、置信度和操作按钮。
- 模式按钮为「顔認識」「物体認識」。切换时显示「認識モードを切り替えています」，停止当前推理、释放模型，再加载目标模型。
- 识别框标签：人脸模式显示姓名或「未登録」；物体模式显示日语类别名与百分比。
- COCO 内部类别保持官方索引，UI 使用固定的日语标签表；无法翻译的类别回退到官方英文名，不能显示错误类别。

### 5.2 人员录入

1. 点击「人物を登録」。
2. 使用现有 LVGL 键盘交互样式输入姓名。
3. 姓名去除首尾空白后必须非空，按 UTF-8 字节限制长度；同名时要求用户先删除或选择重新录入。
4. 页面依次提示正面、轻微左转、轻微右转等姿态，并显示 `1 / 5` 至 `5 / 5`。
5. 每次采样只接受“恰好一个人脸、尺寸足够、置信度达标”的结果；阈值是可校准常量，初值以官方示例为依据，真机数据决定最终值。
6. 5 次合格采样完成后提交数据库与姓名映射，并显示「登録しました」。任一步骤取消或失败都不得留下半条人员记录。

管理页最多列出 10 人，提供「削除」「再登録」。删除前显示页内确认，成功后显示「削除しました」。

### 5.3 人脸识别结果

- 已知人员：框上显示 `<姓名> <百分比>`，结果区显示「認識しました」。
- 未知人员：框上显示「未登録」，结果区显示「未登録の人物です」。
- 无人脸：显示「顔が見つかりません」。
- 多张人脸：逐框显示；右侧主结果采用最高相似度目标，并显示总人数。
- 低于匹配阈值一律视为未注册，不得猜测姓名。匹配阈值必须保留真机校准入口。

### 5.4 物体识别结果

- 有结果：逐框显示日语类别与百分比，结果区显示「N件検出しました」。
- 无结果：显示「対象が見つかりません」。
- 默认只显示最高置信度的有限数量框，先按置信度过滤并排序；上限与阈值保留为可调常量，避免 800×480 画面拥挤。
- COCO 推理不承诺视频帧率。预览持续刷新，推理以单任务串行执行；结果在下一次完成前保留，并显示「認識中…」。

## 6. 日语状态文案

| 场景 | 画面文案 |
| --- | --- |
| 相机初始化 | `カメラを準備しています` |
| 模型加载 | `認識モデルを読み込んでいます` |
| 正在推理 | `認識中…` |
| 人脸成功 | `認識しました` |
| 陌生人 | `未登録の人物です` |
| 无人脸 | `顔が見つかりません` |
| 物体成功 | `N件検出しました` |
| 无物体 | `対象が見つかりません` |
| 录入提示 | `正面を向いてください` / `少し左を向いてください` / `少し右を向いてください` |
| 录入成功 | `登録しました` |
| 录入失败 | `登録に失敗しました` |
| 删除成功 | `削除しました` |
| 通用推理失败 | `認識に失敗しました` |
| 相机异常 | `カメラを確認してください` |
| 模型异常 | `認識モデルを読み込めません` |
| 存储异常 | `登録データを保存できません` |

失败状态使用红色强调，成功状态使用绿色强调，处理中使用现有青色强调。颜色之外必须始终有文字，不能只靠颜色表达状态。

## 7. 持久化与隐私

- 使用官方 `HumanFaceRecognizer` / `dl::recognition::DataBase` 保存特征数据库。
- 复用现有 `storage` SPIFFS 分区；实现时增加一次挂载和卸载路径，并验证该分区未被其他业务使用。
- 另存一份版本化人员元数据，将官方特征 ID 映射到 UTF-8 姓名及人员槽位。
- 元数据采用临时文件写入、同步、原子重命名，防止掉电留下半文件。
- 启动时验证版本、人数上限、名称长度、特征 ID 数量和文件大小；损坏时保留文件并提示存储错误，不静默清空。
- 删除人员时先更新官方特征库，再原子更新元数据；失败时在 UI 显示错误并重新加载磁盘状态。
- 不保存预览帧、人脸裁剪图或识别历史。

## 8. 生命周期、并发与错误恢复

- 进入 Vision 页面：挂载人员存储、启动相机、启动预览、加载默认「顔認識」模型、启动推理任务。
- 离开 Vision 页面：停止接收新帧、等待当前推理安全结束、停止相机、释放转换缓冲与模型；人员数据库完成同步后卸载。
- 切换模式：禁止并发推理；停止当前模型后再创建目标模型。失败时保留预览并显示模型错误，允许重试或返回首页。
- 服务使用一个状态锁和一个有界命令/结果通道即可，不增加通用事件总线或插件抽象。
- 连续相机错误达到有限次数后停止采集并提示「カメラを確認してください」；用户重新进入页面时重试初始化。
- 分配失败、模型加载失败和文件系统错误必须返回明确状态，不触发重启循环。
- 语音服务继续常驻；若内存实测表明语音与 Vision 无法共存，视为兼容性门槛失败并记录数据，不得静默停止 WakeNet。

## 9. 模型与资源选择

- 人脸检测首选官方最小可用模型；候选为 `ESPDET_PICO_224_224_FACE`，与 `MSRMNP_S8_V1` 在 S31 真机上比较内存、速度和召回后确定。
- 人脸特征首选较轻的 `MFN_S8_V1`；只有在空间和延迟均通过后才考虑更大的 `MBF_S8_V1`。
- COCO 首选 `YOLO11N_320_S8_V1`，不默认采用 640×640 模型。
- 模型位置优先 Flash rodata，因为当前分区中的 `model` 已用于 ESP-SR，`storage` 用于人员数据库。若 app 分区放不下，必须先提交分区与烧录影响评估，再选择独立分区或 SD 卡；不得覆盖语音模型。
- 模型切换采用释放后再加载，不预加载两个模型。

## 10. 验证与验收

### 10.1 自动检查

- 主机侧状态机测试：进入/离开、模式切换、成功、陌生人、空结果、相机/模型/存储失败。
- 人员元数据测试：空库、录入 5 次、重复姓名、10 人上限、删除、重启恢复、损坏文件。
- 坐标映射测试：模型输入框正确映射到裁剪/旋转后的 520×310 预览。
- UI 源码回归：所有必需日语文案存在，旧的模拟「妖怪探索」按钮逻辑被移除。
- 原有 `test_ui_regression.py` 与 `check_voice_integration.py` 必须继续通过。

### 10.2 构建与静态资源

- 使用项目现有 ESP-IDF master 环境为 `esp32s31` 完整构建。
- 记录 app、Flash 模型、内部 RAM 与 PSRAM 占用；不得越过分区边界。
- 检查所有新增日文字符已包含在 CJK 字体子集，真机不得显示豆腐块。

### 10.3 真机验收

- 连续进入/退出 Vision 页面 20 次，无崩溃、内存持续下降或相机占用残留。
- 两种模式来回切换 20 次，模型不重叠常驻，失败能恢复。
- 录入 3 名测试人员，每人 5 次采样；重启后姓名和身份可恢复。
- 已录入者、未录入者、无人脸、多张人脸分别显示正确日语状态。
- 用一组覆盖常见 COCO 类别的实物验证框、日语标签和置信度；无目标时显示空结果。
- 拔掉或遮挡相机、制造模型或存储失败时，页面显示对应日语错误并可返回首页。
- Vision 运行前后复测「Hi ESP」与「画像」，确认全局唤醒和页面跳转未退化。
- 记录相机预览 FPS、人脸推理耗时、COCO 推理耗时、峰值内存与最低剩余内存。性能结果作为实测数据呈现，不在实现前虚构目标帧率。

## 11. 非目标

- 不保存或上传照片、识别历史与考勤记录。
- 不做云端识别、活体检测、防照片攻击或权限系统。
- 不训练自定义模型，不增加 COCO 之外的类别。
- 不让人脸和 COCO 模型同时推理。
- 不重构其他应用，不改动已验收的语音词表和声学参数。
- 不在本阶段适配其他开发板。
